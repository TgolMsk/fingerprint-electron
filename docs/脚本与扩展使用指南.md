# 脚本与扩展使用指南

适用：工作台 `0.3.0`、FP SDK `0.1.0`。开发者接入接口见 [SDK 二次开发指南](../fp-sdk/README.md)。

## 打开管理窗口

正常关闭旧工作台后，重新双击项目根目录的 `启动指纹测试.cmd`，在顶部点击 **脚本与扩展**。管理窗口分为“脚本”“扩展”“执行日志”三个页签；账号网页仍在原来的内嵌实例中运行。

## 导入、新建和执行脚本

1. 点击“新建”，或先选择右侧目标实例，再点击“导入 .js 文件”。文件须小于 1 MB。
2. 填写名称、代码、目标实例和匹配网址。“启用”控制脚本是否允许执行。
3. 选择“仅手动”或“页面加载完成后”，点击“保存脚本”。自动执行从下一次完整页面加载开始。
4. 手动运行时点击“执行已保存脚本”，运行的是保存的版本；编辑器里未保存的修改不会执行。
5. 在“执行日志”中展开记录，查看实例、时间、URL、返回值、console 输出和错误。可导出最近可见记录为 JSON。

可直接复制的测试代码：

```js
console.log('当前网页', location.href);
document.body.dataset.fpScriptChecked = 'yes';
return {
  title: document.title,
  language: navigator.language,
  timezone: Intl.DateTimeFormat().resolvedOptions().timeZone
};
```

先在当前实例打开 HTTP(S) 网页，再选中该实例保存并运行。成功后日志显示 `success`，返回当前实例页面的标题、语言和时区。想验证隔离，可只在实例 1 执行，再在各实例 DevTools 查询 `document.body.dataset.fpScriptChecked`。

匹配网址每行一条，`*` 是通配符。例如 `https://example.com/*` 只用于该地址范围；本地测试页可填写 `http://127.0.0.1:*/*`。手动执行同样检查网址范围。

代码支持 `await`、`return`，可读取和修改 DOM；运行在隔离的网页 JS 环境，不能直接使用 Node、`require`、宿主接口、页面主世界变量或油猴 `GM_*` API。只在主页面执行，不遍历所有 iframe；SPA 内部路由切换不触发“加载后执行”。

| 日志状态 | 意义与操作 |
| --- | --- |
| success | 当次脚本执行结束并返回结果 |
| error | 查看 error 字段；可能是代码错误或实例不可用 |
| skipped | 网址不匹配，或实例仍有脚本未结束 |
| timeout | 超过 10 秒等待；代码可能仍在运行，刷新该实例后重试 |

超时不会强制终止 JavaScript；代码造成页面无响应时需要重启程序。日志不是完整浏览器控制台，只保存当次脚本包装器捕获的输出，超长内容会截断。删除脚本不会撤销已经发生的页面修改。

## 导入和管理扩展

1. 准备包含 `manifest.json` 的**解压扩展目录**。当前不直接安装 Chrome 商店链接或 `.crx` 文件。
2. 打开“扩展”页签，勾选需要加载的实例，点击“导入扩展目录”。
3. 检查每个实例旁边的状态；“已加载”只表示该实例初始化成功。
4. 刷新已有网页，验证扩展注入是否生效。使用对应实例的“打开弹窗”测试扩展操作界面。
5. 取消某实例勾选即可停用；重新勾选可启用。启停后刷新已有网页。
6. 正常退出、重开工作台，已启用的扩展会恢复。停用状态也会保留。
7. 点击“卸载”会取消整个扩展在所有实例的登记，保留原目录、导入副本和已有存储。

导入会复制文件，之后修改原目录不会自动更新扩展。固定 key 的同一扩展不能重复登记，可在其现有卡片中为其他实例启用。目前更新需要卸载后重新导入，没有自动更新器。

“打开弹窗”使用该实例自己的 Session；没有声明 default_popup 的扩展会提示无弹窗。当前弹窗只访问扩展本身页面，不支持从中打开外部登录网站。“诊断”展示 runtimeId、加载错误和活动后台上下文；其中 `not-tested` 表示未替你执行实际业务验收，不是失败。休眠的 MV3 worker 可能不出现在当前活动列表。

## 自己复核常规兼容性

项目提供 MV2 和 MV3 两个测试扩展：`fp-sdk/tests/fixtures/mv2`、`fp-sdk/tests/fixtures/mv3`。它们不需要账号或外网，内容脚本只匹配 `http://127.0.0.1/*`。

导入到两个实例并打开本地指纹页，刷新后，在实例 DevTools 执行：

```js
({
  mv2: document.documentElement.dataset.fpMv2,
  mv2Background: document.documentElement.dataset.fpMv2Background,
  mv3: document.documentElement.dataset.fpMv3,
  mv3Background: document.documentElement.dataset.fpMv3Background
})
```

导入对应版本后，页面注入结果应为 `injected`，后台回复应为 `mv2` 或 `mv3`。未导入的版本为 undefined 属于正常情况。测试扩展弹窗显示 `ready`。

自动验收另外验证 popup 内 `chrome.storage.local` 的写入、两实例隔离、跨进程保留，以及按实例停用和卸载。运行：

```powershell
node 'D:\project\webtt\fp-sdk\tests\run.js'
```

输出路径中有 `summary.json`、每阶段详细记录、stdout/stderr 和管理窗口截图。最新结果见 [扩展与 SDK 验收报告](../fp-sdk/COMPATIBILITY.md)。

这套验收说明常规基础链路可用，不覆盖所有 Chrome 扩展 API。之后选定真实插件时，应分别验证注入、后台任务、弹窗、存储、启停和重启；依赖标签页管理、浏览器工具栏、云同步或外部登录的插件，需要继续评估。

## 文件与备份

脚本、扩展登记、日志和导入副本位于 `%APPDATA%\fp-demo\automation`；使用自定义 `--user-data-dir` 时随该目录改变。扩展自己的存储位于各实例分区。正常退出后备份整个 userData，不能只备份 `accounts.json`。

当前扩展登记使用绝对目录，恢复时应保持原路径；跨目录/跨机器迁移尚未提供自动工具。脚本和日志可能包含页面数据，备份与导出应按普通账号资料管理。
