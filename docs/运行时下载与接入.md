# 运行时下载、安装与现有 Electron 应用接入

本项目提供已经编译好的定制 Electron 运行时。Electron 程序和 Chromium 指纹内核在同一个发行包中，不需要分别安装。开发界面或接入现有应用时可以直接使用；修改 C++ 补丁、升级内核版本或增加平台时才需要重新构建。

## 1. 下载哪个版本

发布页：[v44.4.5-fp0.1.0-testing.1](https://github.com/TgolMsk/fingerprint-electron/releases/tag/v44.4.5-fp0.1.0-testing.1)。

| 项目 | 内容 |
| --- | --- |
| 平台 | Windows x64 |
| Electron / Chromium | 44.4.5 / 152.0.7977.130 |
| 内嵌 Node.js / FP Kernel | 24.21.0 / 0.1.0 |
| 构建配置 | testing，symbol_level=0 |
| 运行时 ZIP 大小 | 210,490,153 字节，约 200.74 MiB |
| 发布性质 | 预发布版，用于接入和验收；不是优化 release 构建或安装器 |

附件用途如下：

GitHub 自动生成的 `Source code (zip/tar.gz)` 仅包含 Git 源码，不包含 `electron.exe`。运行时必须单独下载，不需要克隆数百 GB 的 Chromium 构建目录。

## 2. 下载、校验并启动本项目

先获取本标签的源码：

```powershell
git clone https://github.com/TgolMsk/fingerprint-electron.git
cd fingerprint-electron
git checkout v44.4.5-fp0.1.0-testing.1
```

也可解压发布页的 `fp-lab-source-44.4.5-fp0.1.0.zip`，然后在其根目录打开 PowerShell。下载三个配套文件：

```powershell
$ReleaseBase = 'https://github.com/TgolMsk/fingerprint-electron/releases/download/v44.4.5-fp0.1.0-testing.1'
$RuntimeName = 'fp-electron-44.4.5-fp0.1.0-win32-x64-testing.zip'
New-Item -ItemType Directory -Force -Path '.\downloads' | Out-Null
foreach ($Suffix in @('', '.sha256', '.validation.json')) {
    Invoke-WebRequest -Uri "$ReleaseBase/$RuntimeName$Suffix" -OutFile (Join-Path '.\downloads' "$RuntimeName$Suffix")
}
$RuntimeArchive = (Resolve-Path (Join-Path '.\downloads' $RuntimeName)).Path
$ExpectedHash = '62d896545153da78ba74d7dac387da0a42da024e0ba2f2c45cf26503be52de4b'
if ((Get-FileHash -LiteralPath $RuntimeArchive -Algorithm SHA256).Hash.ToLowerInvariant() -ne $ExpectedHash) {
    throw '运行时 SHA256 不匹配，请重新下载并检查来源。'
}
python fp-kernel/scripts/release.py install-runtime --archive $RuntimeArchive --project .
if ($LASTEXITCODE -ne 0) { throw '运行时安装失败，请查看上面的错误。' }
.\启动指纹测试.cmd
```

校验安装需要 Python 3.11 或以上。安装后双击启动无需 Node.js、Python 或完整编译工具链。脚本会检查运行时内容和验收结果，再写入 `runtime/current.json`；账号数据不在运行时 ZIP 中。重复安装同一版本不会覆盖现有目录，已安装时直接启动即可。

更换运行时后正常退出应用再启动。回退命令和数据备份说明见 [构建迁移与发布](构建迁移与发布.md) 与 [项目使用手册](项目使用手册.md)。运行时回退不等于 Chromium 用户数据可以任意跨版本降级。

## 3. 接入已有 Electron 应用

必须同时修改开发启动和应用打包配置。仅在 `package.json` 修改 `electron` 版本号，仍然会下载普通 Electron；仅复制 `electron.exe` 也会缺少配套文件。

### 准备完整运行目录

从本项目根目录执行以下示例。目标目录需不存在或为空；路径按宿主项目实际位置调整：

```powershell
python fp-kernel/scripts/release.py verify-package --archive $RuntimeArchive --extract '../my-app/vendor/fp-electron'
```

将宿主项目的 `vendor/fp-electron/` 和下载目录加入它自己的 `.gitignore`，不要将运行时二进制提交进源码历史。保留运行时中的许可证文件。

### 开发启动

保留宿主原有前端构建、Vite 和 TypeScript 流程；把最终启动 Electron 的步骤指向定制程序。在宿主项目根目录，例如：

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
& '.\vendor\fp-electron\electron.exe' .
```

这只展示运行时选择，主进程和前端仍须按宿主项目原来的方式构建或启动。Electron 类型依赖与目标版本应对齐并锁定；若依赖原生 `.node` 模块，需要验证 ABI 并按目标 Electron 重新构建。

### electron-builder 打包

将下面两个字段合并进宿主现有 `build` 配置，保留原有 `appId`、文件规则和安装器设置：

```json
{
  "build": {
    "electronVersion": "44.4.5",
    "electronDist": "vendor/fp-electron"
  }
}
```

`electronDist` 指向已经校验并解压的完整目录。本项目 ZIP 采用自己的版本化命名，不要假定打包器会自动识别该名称。先生成目录版应用，例如 `npx electron-builder --win --x64 --dir --publish never`，启动验收后再生成安装器。最终安装包包含宿主应用和定制运行时，用户不需要另装普通 Electron。

参考：[electron-builder v26 electronDist 配置](https://www.electron.build/v26/docs/api/app-builder-lib.interface.configuration/#electrondist)、[Electron 原生模块说明](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)。

### 指纹配置和会话管理

1. 每个账号使用稳定、独立的持久化 Session Partition。
2. 在创建该账号的 `WebContentsView`、首次导航之前，调用对应 Session 的 `setFingerprintConfig(JSON.stringify(fp))`。保存指纹配置，重启时恢复同一配置，避免每次启动随机变化。
3. 将宿主已有 UA 设置与指纹配置协调一致，检查请求头和页面读数；保留代理、权限和扩展加载的初始化顺序。
4. 启动时检查 `typeof session.setFingerprintConfig === 'function'`，如果误用了普通运行时应明确报错。
5. SDK 是可选封装，也可直接调用原生接口。配置结构与示例见 [SDK 接入指南](../fp-sdk/README.md) 和 [双账号示例](../fp-sdk/examples/embedded.js)。

仅替换运行时不会自动给每个账号生成不同指纹。定制宿主还应使用自己的更新发布渠道，保证后续安装包继续包含定制运行时。

## 4. 验收范围与后续发布

本运行时已通过内核 206、三账号 91、工作台 58、SDK 45，共 400 项功能验收，以及 27 项构建发布流程测试。完整构建使用独立源码和空输出目录，复用固定下载缓存；尚未完成全新操作系统无缓存重建、另一台机器或第三方宿主应用的验收。

宿主接入后应测试登录、会话隔离、指纹重启一致性、扩展、弹窗、下载、更新和实际打包结果。本发布不代表所有 Chrome 扩展兼容，也不代表所有外部指纹检测通过；既有 CreepJS 检测仍有 Rects / Audio 相关的 4 lies。详见 [公开检测报告](../fp-kernel/reports/phase5/REPORT.md)。

GitHub 的 **Pre-release** 是发布状态；GN 的 **testing/release** 是编译配置，两者不同。当前附件是 testing 构建，未签名。正式交付前需完成优化 release 构建及相应验收、宿主安装器和更新验证。macOS、Linux、ARM64 需要分别构建和验证，不能复用 Windows x64 二进制。
